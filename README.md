# Sistema de Gerenciamento de Biblioteca - Flutter & Supabase

Aplicação web e mobile desenvolvida em **Flutter** com integração ao **Supabase**, projetada para o gerenciamento completo de um acervo literário pessoal, contando com autenticação segura e isolamento de dados por utilizador.

## 1. Descrição do Aplicativo

Este aplicativo foi construído para permitir que utilizadores registrem, visualizem e gerenciem livros de uma biblioteca digital de forma prática e intuitiva. O sistema conta com uma interface limpa e moderna, separando o acesso através de contas de utilizador seguras, garantindo que cada pessoa visualize apenas os seus próprios livros cadastrados.

## 2. Funcionalidades Principais

* **Autenticação de Utilizadores:** Criação de conta (registo) e login, comunicando diretamente com o serviço de autenticação do Supabase de forma dedicada.

* **Gerenciamento de Acervo (CRUD Completo):**

  * **Cadastrar Livro:** Registo de novos livros informando o título, autor e ano opcional de publicação.

  * **Listar Acervo:** Visualização em formato de cartões limpos (Cards) com avatares dinâmicos e indicação de autor e ano.

  * **Excluir Livro:** Remoção de registos com caixa de diálogo de confirmação prévia para evitar exclusões acidentais.

* **Segurança e Controlo de Sessão:** Proteção de rotas e encerramento de sessão (*Logout*) integrado no cabeçalho (*AppBar*).

## 3. Tecnologias Utilizadas

* **Frontend:** Flutter & Dart.

* **Backend & Base de Dados:** Supabase (PostgreSQL).

* **Autenticação:** Supabase Auth (auth.users).

* **Hospedagem Web:** GitHub Pages.

## 5. Descrição da Autenticação e da Base de Dados

### Autenticação

* O sistema utiliza o **Supabase Auth**.

* As credenciais (e-mail e palavra-passe) são geridas e encriptadas automaticamente nos servidores do Supabase (esquema interno auth.users), gerando tokens de sessão seguros para o utilizador autenticado sem expor dados sensíveis no código da aplicação.

### Base de Dados (PostgreSQL)

A base de dados é composta por uma tabela chamada livros, criada com a seguinte estrutura SQL:

create table livros (
  id bigint generated by default as identity primary key,
  titulo text not null,
  autor text not null,
  ano int,
  user_id uuid references auth.users(id) default auth.uid(),
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

### Segurança (RLS - Row Level Security)

A tabela possui o **RLS ativado**, garantindo que cada utilizador apenas consiga interagir (ler, criar, atualizar ou apagar) com os registos em que o user_id corresponda à sua própria sessão ativa:


alter table livros enable row level security;

create policy "Usuários podem gerenciar seus próprios livros" 
on livros for all 
using (auth.uid() = user_id);
